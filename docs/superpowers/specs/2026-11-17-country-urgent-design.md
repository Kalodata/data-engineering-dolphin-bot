# 各国天级任务全员加急

已确认规则：TikTok 天级任务按国家当地日期检查前一天的数据；完成截止为当地 13:00，印尼为雅加达 15:00。未成功完成（包括运行、失败、暂停、停止、未开始）发送群消息并给群内所有用户发应用内加急。欧洲超时未开始阈值统一为北京时间 15:30；其余国家保留当地 02:00。沿用当前看板国家和通知群。

采用独立每分钟检查器，避免现有每日四次看板推送错过国家截止时间。相比绑定看板推送，独立检查可以准点发现；相比增加 DS 调度任务，部署和状态管理仍留在 bot。现有看板与检查器共用截止时间，欧洲文案明确显示北京时间 15:30。

以国家、当地数据日、告警类型去重；同一轮异常汇总为一条消息。状态以原子 JSON 写入 .data，记录已检查项、消息 ID 和尚未加急的用户。加急失败重试原消息；已成功的用户批次不重发。同一存储保留时进程重启可恢复，ECS 换容器的临时磁盘不保证保留去重记录。

数据查询基于工作流 globalParams 的 country_code/data_date，独立于北京时间当日实例名称，覆盖美洲跨北京时间午夜和夏令时。查询失败、详情缺失或分页未完整读取时不把国家误报为未开始。检查最新实例，仅 SUCCESS 视为完成。

飞书操作使用 bot 身份、现有 profile。完整分页获取真实用户成员，排除机器人；超过 200 人分批加急。群成员列表不完整或权限失败时保留待发送状态，不伪报全员成功。发送消息使用持久化幂等键。所需权限为群成员读取和应用内加急。

验证覆盖欧洲 15:29/15:30、当地 12:59/13:00、印尼 14:59/15:00、跨日和夏令时、成功不提醒、各种未完成状态、无实例、重启去重、查询失败、部分发送失败、成员分页和超过 200 人分批。禁止向真实群发送测试加急。

查询使用近三天至次日的 DS startDate/endDate 范围；整轮查询默认 45 秒超时（query_timeout_ms 可调整）。参数按开始时间筛选的依据是 [Apache DolphinScheduler 3.2.2 mapper](https://github.com/apache/dolphinscheduler/blob/3.2.2/dolphinscheduler-dao/src/main/resources/org/apache/dolphinscheduler/dao/mapper/ProcessInstanceMapper.xml)。
